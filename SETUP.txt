Master Button — dedicated Azure key setup

This repository-owned plain-text document has no website JavaScript.
Enable the installed Master Button userscript for this page.
The installed alpha.2 or later opens Speech setup automatically.
If it does not, open its launcher → More → Speech setup.
Both /main/SETUP.txt and /refs/heads/main/SETUP.txt URLs are supported.
Alpha.5 shows pasted-key, saving, verified and failure feedback beside Save key.
If the extension bridge is unavailable, saving explains the failure here.
A failed save keeps your pasted key. No website storage fallback is used.
After updating the script, open the Userscripts extension popup fully,
check access to raw.githubusercontent.com, then reload this document.
Enter your own Azure Speech resource key, choose its region, and save.
The key is written through Userscripts' extension storage in this userscript's filename scope.
No synthesis occurs when saving a key. The selected region’s voice list loads
automatically from Azure using that key, without sending article text. A voice demo, Play, or Prepare MP3 sends a request only when you choose that action.
Never put your key in a URL, issue, repository file, screenshot, or chat message.

An arbitrary webpage can observe keyboard events around an injected form.
Master Button therefore disables new key entry on other webpages.
This dedicated-page workflow still requires a physical Safari/Userscripts check.
If it is unavailable on your installed extension, do not type the key on an untrusted page.
Existing separately stored speech keys are preserved and can be imported by their exact extension key name from the same userscript filename.

If entry/save still fails in alpha.5: run Check extension storage beside
the key controls. Expand Connection checks to Copy support report. No key is needed.
The report contains no keys, headers, stored values or page content.
